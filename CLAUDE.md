# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Three-point polar alignment (like NINA's TPPA) for ZWO Seestar telescopes in EQ mode. A single static Go binary (stdlib only, no third-party modules, `CGO_ENABLED=0`) serves a web UI. It drives the Seestar over **ASCOM Alpaca** and plate-solves with the external **`astap_cli`** binary.

## Commands

```sh
make test                 # go vet ./... && go test ./...
make build                # -> bin/seestaralign
make run                  # build, then serve on 127.0.0.1:8080 (tick "Simulator" in the UI)
make linux-amd64 / linux-arm64
make reference            # regenerate testdata/reference.json from astropy (needs uv)

go test ./internal/polar -run TestAdjustmentTracksKnobTurns -v   # single test
```

The `internal/session` tests run full simulated alignments in real time and take about 30 s. No real hardware or ASTAP install is needed for any test. ASTAP is faked with a shell script named `astap_cli` written to a temp dir, and Alpaca is faked with an `httptest` server that wraps the simulator (`alpaca_fake_test.go`).

Binary flags: `-listen`, `-config` (settings JSON; default comes from `$SEESTARALIGN_CONFIG`, then `$STATE_DIRECTORY`, then the user config dir), `-workdir` (where `frame.fits` is written for ASTAP).

## Architecture

The data flow is `web` → `session` → (`Rig`, `frameSolver`) → `astro`/`polar`.

- **`internal/session`** is the core. `Session` holds one mutex-guarded `State` struct, and that struct *is* the API: `web` serialises it whole for `GET /api/state` and pushes it on every change over SSE (`/api/events`). To change state, call `s.update(func(st *State){...})` or hold `s.mu` and call `notifyLocked()`. Any new UI-visible field goes into `State`, and `internal/web/static/index.html` reads it.
  - `Rig` interface (`rig.go`): telescope plus camera. It has two implementations, `alpacaRig` (real) and `simRig` (`sim.go`, which models a mount with a known polar error, renders synthetic starfields and has knob controls). `simSolver` returns the simulator's ground truth in place of running ASTAP.
  - `frameSolver` interface: `astapSolver` writes a 2×2-binned FITS file and shells out to ASTAP. It retries with other Seestar models that have the same sensor size, and returns the model key that matched so the session can correct the detected model.
  - `measureAndAdjust` is the routine. It runs 3 × (expose → solve → `astro.PointingVector`) with `moveRA` (MoveAxis on axis 0 only) between frames, then calls `polar.FitAxis` and `ComputeError`, then loops forever on `polar.Tracker.Update` until cancelled. `run()`'s defer always sends `MoveAxis(0)`. Keep that guarantee, and also the Dec-drift and RA-didn't-move aborts in `moveRA`.
  - Phases: `disconnected → connecting → ready → measuring → adjusting`.
- **`internal/astro`**: coordinate math in an Earth-fixed horizon frame (**x = north, y = east, z = up**, which is left-handed, so the sky turns as a *positive* rotation about the NCP vector). The steps are J2000 solve → precess to date → alt/az at mid-exposure → optional refraction. All polar math works on these unit vectors. Tests check against astropy values in `testdata/reference.json`, which is generated by `tools/gen_reference.py` and committed. Regenerate it only when the coordinate math changes.
- **`internal/polar`**: `FitAxis` finds the normal of the plane through the 3 points. `Tracker` solves `P(t) = K·R(A0, ω(t−t3))·P3` for the two knob angles (K = Rz(α)·Ry(β)). Each frame is solved against point 3, never against the previous frame. The package doc comment derives this. Read it before changing the math.
- **`internal/alpaca`**: minimal Alpaca HTTP client (with binary `ImageBytes` and a JSON fallback), UDP discovery and its own mDNS resolver for `seestar.local` (no avahi needed). The Seestar's native Alpaca port is 32323.
- **`internal/solver`**: wraps `astap_cli`, finds the binary and star databases, and parses its `.ini` output. It distinguishes `ErrNoSolution` (retryable) from fatal errors (missing DB, or the GUI build in place of `astap_cli`).
- **`internal/models`**: Seestar optics table (S30/S30 Pro/S50/S50 Pro). The S30 and S50 share a sensor size, and so do the two Pro models, so detection from the sensor alone is ambiguous. That is why plate-solve correction exists.
- **`internal/web`**: routes in `server.go`. The UI is one embedded file, `static/index.html` (vanilla JS, no build step).

## Deployment notes

- Docker (`Dockerfile`, `compose.yaml`) bundles `astap_cli` and a star DB, chosen with `--build-arg ASTAP_DB=d50|d80|d05|none`. It must use **host networking** so mDNS and Alpaca UDP discovery reach the LAN.
- `deploy/seestaralign.service` is a hardened systemd unit (DynamicUser, StateDirectory).
- The host clock matters: 1 s of error is 15″ of sky rotation. The app can sync the Seestar's clock, because the Seestar has no RTC.

## Unverified on real hardware (per README)

- Whether `MoveAxis(0, rate)` really turns RA in EQ mode.
- Whether the camera supports binary `ImageBytes`.
- What the Pro models call their wide-angle camera. Cameras named "wide" or "guide" are skipped, and `camera_num` in the settings overrides the choice.

Treat these as open questions when debugging reports from real hardware.
